# 법무법인 호경 개인회생 상담 랜딩페이지

카드형 개인회생 상담 신청 페이지입니다. 실제 신청 정보를 서버 SQLite DB에 저장합니다.

## 포함 기능

- `/lp/[campaign]` 캠페인별 랜딩페이지
- 상담 안내 → 현재 채무액 → 월 소득 → 이름·전화번호·개인정보 동의 → 완료 화면
- 첫 방문·UTM 저장, 질문별 다음 버튼에서 답변 저장
- 방문 쿠키를 이용한 진행 복원 및 최종 신청 중복 저장 방지
- 최종 제출 성공 시 `completed=1` 및 동의·완료 시각 저장
- 개인정보 수집 주체: 법무법인 호경 / 보유기간: 수집일로부터 1년
- 모바일 대응, 서버 입력 검증, 타 출처 요청 차단

관리자 화면, Google Sheets 연동, 웹훅은 포함하지 않습니다. 이름·전화번호는 최종 동의 제출 때만 저장합니다. 실제 상담 알림은 발송하지 않습니다.

## 로컬 실행

Node.js 22.13 이상이 필요합니다. 외부 패키지 설치는 필요 없습니다.

```sh
node scripts/serve.mjs
```

접속: http://127.0.0.1:5173/lp/hokyung

`/lp/naver`, `/lp/meta`처럼 주소 끝을 바꾸면 캠페인별로 방문 기록을 구분합니다. 문구·질문은 동일합니다.

```sh
node test/api.test.mjs
```

## 데이터

기본 DB 파일: `data/consultations.sqlite`. 서버 재시작 후에도 유지됩니다. 이 파일과 WAL 파일에는 신청자 정보가 있으므로 저장소에 올리지 마세요. 실제 DB와 인증키는 소스에 포함하지 않습니다.

`visits`에 방문 시각, 마지막 저장 시각, 캠페인, UTM, 단계, 답변, 이름, 전화번호, 동의 시각, 완료 여부를 저장합니다. 미완료 레코드와 마지막 저장 시각으로 중간 이탈을 분석할 수 있습니다. 관리·다운로드 API는 없으므로 DB 파일에 접근할 수 있는 운영자가 조회해야 합니다.

보유기간이 지난 기록은 방문 요청 시, 서버 시작 시, 실행 중 매일 정리합니다.

## 서버 배포

GitHub 저장소는 코드 보관·배포 준비용입니다. **GitHub Pages는 정적 호스팅이므로 이 프로젝트의 DB 서버를 실행할 수 없습니다.** 실제 광고용 공개 URL은 Node.js 또는 Docker 서버에서 HTTPS로 운영해야 합니다.

환경변수:

| 이름 | 기본값 | 설명 |
|---|---|---|
| `HOST` | `127.0.0.1` | 서버에서 외부 요청 수신 시 `0.0.0.0` |
| `PORT` | `5173` | 수신 포트 |
| `SQLITE_PATH` | `data/consultations.sqlite` | 영속 디스크의 DB 경로 |
| `PUBLIC_ORIGIN` | 없음 | HTTPS 프록시 운영 시 실제 사이트 원점, 예: `https://example.com` |

Docker 로컬 실행:

```sh
docker compose up --build -d
```

Compose는 로컬 5173 포트를 열고 DB를 named volume에 보관합니다. 실제 운영에서는 HTTPS 프록시와 `PUBLIC_ORIGIN`을 설정하세요. 영속 디스크를 제공하지 않는 일회성 파일시스템에 배포하면 재배포 시 DB가 사라질 수 있습니다. 같은 SQLite 파일을 여러 독립 서버가 동시에 쓰는 구성은 피하세요.
